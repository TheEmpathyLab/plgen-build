## Decisions made

- **Coach is session-bound by design** — no pasted labels from outside the current session. Integrity of coaching depends on having witnessed the work. Non-negotiable.
- **Three-state model** — State 1 (at/near baseline): affirm and close. State 2 (below baseline, recoverable): 3 questions, "I'll wait." State 3 (< 30% human): input playbook, no rewrite suggestions, "Don't turn it in yet."
- **Baseline personalization for members** — calls `GET /api/members/average` silently. Degrades gracefully to 85% if endpoint unavailable or session_count < 3. Endpoint not yet built — prompt handles both cases.
- **`ai_instructions/` as the skills library** — existing folder structure is already the right home for skill files. No new folder needed.

## PLGen Skills System — strategic direction established

The session surfaced a major product direction: PLGen as a community skills directory, modeled on Obsidian's plugin ecosystem.

**Core insight:** PLGen owns the standard and the registry, not the prompts. Anyone who understands the skill format can write and publish a skill. `provenancelabel.org/skills` becomes a community directory — not a page Shelton maintains alone.

**The institutional use case** is the most powerful surface: a professor or university publishes a PLGen skill scoped to their course, department, or field. A biology lab and a creative writing program have completely different standards for responsible AI use. PLGen provides the framework; the institution provides the context.

This connects to prior work at Operable (Cog) — community-contributed commands, shared via a directory, core team owns the runtime and standard, not the content.
